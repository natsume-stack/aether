**改动半径评估（对象存储/CDN 或纯静态目录 + 客户端缓存）**：
- **已内置一半**：发布期 `assetMode='oss'` → S3 兼容签名上传公开 runtime blob（`asset-distribution.js:47-48,127-147`；`exportPlayBundle:2794-2801`），包内 manifest 记 `assetDistribution{provider,endpoint,bucket,hashes}`，`copyReleaseWorld:2695-2733` 据此**跳过**已外置哈希的复制，但脚本/权限类 private blob 恒留包内。→ 改动半径：引擎侧只读挂载点 1 处（content-host 增加 remote store 适配器——`packages/content-server/src/remote-store-browser.ts` 已是浏览器侧远程读的现成范本），play 前端 URL 解析 2 处（hash-url.ts / server/utils/hash.ts）。**作者契约零变化**（哈希即 URL）。
- 纯静态目录方案：把 `blobs/` 整目录挂 Nginx/`--root` 即可替代 `/block/:hash` GET 面；需保留的语义只有 private 哈希不可达（静态目录必须做 denylist 或干脆不物化 private 文件——注意 deniedHashes 逻辑在引擎进程内，静态化后**必须在打包时就把 private 移出公开目录**，这是唯一新增的破坏面）。POST（编辑期写 blob）不需要出现在部署机上——`/block` POST 只在 creator/edit 模式存在。

## 5. 创作 CLI / MCP 现状与 headless 部署差距

| 组件 | 开源状态 | 事实 |
|---|---|---|
| `apc`（@box3lab/arenapro-cli） | **闭源 npm 二进制**；仓库 0 命中 `apc/arenapro`（grep docs/README/CONTRIBUTING） | 它消费的正是本仓库的 `/api/creator/v1` 协议 |
| `packages/cli`（@box/cli） | 开源，但只是**协议合同**："Stable protocol surface shared by CLI clients and Creator HTTP adapters … contains no HTTP, credential or storage code"（`src/index.ts:1-8`）；定义 `CREATOR_API_PREFIX`、脚本读写 DTO、`parseCreatorProjectScriptWrite`（entry 名 ≤160 且无 `..`、内容 ≤20MiB :76-84） | 版本 0.1.1，private |
| `ap-mcp`（localhost:25315） | 仓库全文 grep `ap-mcp`、`25315` **均 0 命中** → MCP server 由闭源 apc 提供（UNVERIFIED），其能力上限=下述 12 个 HTTP 端点 | — |

**`/api/creator/v1` 全量（12 path，`find apps/game/pages/api/creator -type f`）**：health / projects（列表）/ projects/{id}/resources（`getProjectResources`：modelAssets/pictureAssets/audioAssets/uiTree，`[projectId]/resources.ts:12`）/ runtime + runtime/events（预览运行控制+日志订阅）/ scene/session + action + actions/{requestId} + capture（编辑场景会话，可远程驱动编辑器执行动作与截图）/ scripts + scripts/{side}/{entry}（脚本读写，落 §4 的 `updateProjectScript` 不可变 blob 链，`project-manager.js:2053-2197`）/ storage/{scope}/{space}（project|group 数据空间直读直写，`[scope]/[space].ts:20-26`）。

**CLI token 能力集 = 9 项封顶**（`apps/game/shared/creator-cli-policy.ts:5-15`）：projects.list / resources.list / scripts.read+update / storage.read+write / runtime.view+control / scene.capture。**不含 create/publish/export/package/play-import**。

**今天能脱 GUI 做什么**：改脚本、改数据空间、读资源清单、起停预览、场景截图——**能做**。
**"CI 里 build→upload→publish→可玩"仍缺**：
1. **HTTP 层其实全有**：`POST /api/local-projects`（建图，`index.ts:10-14`）、`…/publish`、`/export`、`/package`、`/snapshots`（路由目录 `apps/game/pages/api/local-projects/[id]/`）、`POST /api/play-admin/library/import`（boxplay 导入，两段式 preview→confirm）——但鉴权走 **玩家浏览器会话 Cookie**（`creator-api-security.ts:77-117`：`allowCreatorApi` 要求 `BOX_DEPLOYMENT_MODE=creator` + host 白名单（默认仅 loopback，:18-27,46-49）+ `resolvePlayerServiceIdentity` 会话 + 创作能力位 :88-105），CLI token 不在这条路上 → **CI 必须先模拟玩家登录**（`/api/player-auth/login` 8 path）。
2. 缺的是：把 publish/export/package/import 提升为 `CreatorCliCapability` 的第 10-15 项（服务端 3 处改动：capability 列表、`allowAuthenticatedCreatorCliApi` 调用点、token 签发 UI），或官方给出 session-cookie 机读登录配方。
3. 文档摩擦（对照 A-docs 18 页）：`docs/first-project.md` 教程 **7 节、约 21 个 GUI 人工步骤**（mermaid 6 阶段 :5-13 + 表格 :36-43,71-77），全程无一条命令式路径；官方"脚本 API"站 `https://docs.box3lab.com/api/` 404（A-docs 已证）；仓库自带文档 `docs/developer-guide.md:99` 只教 `api:generate` 等开发者命令，不提创作 CLI。`internals/apis` 可 `npm run docs` 起本地 swagger-ui（`package.json:25`）——**可用的契约文档已存在但没人指路**。

**UX 结论**：帮助本地开发者"部署一张地图"的最大杠杆不是加功能——发布链、导入链、包格式服务端全齐，缺 (a) CLI token 覆盖发布动词，(b) 一份 10 行 curl 的 headless recipe，(c) 修活 `/api/` 文档 404。
