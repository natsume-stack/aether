# 代码规范

本规范适用于仓库维护的自有代码。上游同步代码、第三方模块和生成物遵循各自约定；具体格式范围以 `scripts/lib/owned-code-config.cjs` 为准。

## 格式与命名

| 项目                  | 约定                                                   |
| --------------------- | ------------------------------------------------------ |
| 文件与目录            | 英文 `kebab-case`                                      |
| 变量与函数 / 类型与类 | `camelCase` / `PascalCase`                             |
| 常量与状态            | 常量用 `UPPER_SNAKE_CASE`；布尔值表达状态，如 `isOpen` |
| 自有 JS/TS、CSS/Less  | 四空格；JS/TS 使用分号、单引号、多行末尾逗号           |
| JSON / Rust           | 两空格、双引号 / rustfmt                               |
| 行宽                  | 100 字符；不截断协议值或不可拆分字符串                 |
| TypeScript 注解       | `value:Type`、`field?:Type`、`read(value:Type):Result` |
| 代码块                | 条件和循环保留花括号；优先提前返回                     |

值不变时使用 `const`，否则用 `let`。名称表达职责，不使用关键字或浏览器内置对象名声明业务变量。对象赋值保留 `field: value`。

## 模块与接口

- 按引用声明、第三方、项目模块、类型和业务代码分组，保留副作用导入顺序。
- 优先具名导出；框架要求的默认导出和外部兼容命名保留。
- 不引入循环依赖，不跨应用直接读取源码；复用能力通过公共包入口共享。
- 内部状态通过明确操作维护，不暴露可变成员或增加隐藏副作用的 getter/setter。
- TypeScript 类成员收紧可见性；原生 `#private` 字段保留原语义。
- 手写模块按职责组织，尽量少于 500 行；不为凑行数机械拆分。

项目内的公共与内部 HTTP API 统一由 `@box/apis` 的 OpenAPI 契约维护：修改契约 → 生成客户端 → 同步调用者与服务端。调用使用生成的命名方法，不手写 `fetch` 或重复拼接 API 路径；不要手改生成文件。数据格式或实时协议变化时，明确旧数据和旧调用方的处理方式。

## 类型、错误与注释

外部 JSON、路径、URL 和网络响应先校验再使用；类型断言不能代替运行时检查。复用契约类型，避免重复 DTO。

错误说明失败操作及可处理原因，不暴露密钥。可恢复错误交由调用方处理，不用空 catch、伪成功或无限重试掩盖失败。清理只处理本次临时文件、锁和子进程。

公共接口用简短 JSDoc 说明职责与副作用。注释解释原因，不复述实现；删除无效注释代码，历史交给 Git。待办使用 `TODO`，合入前处理 `FIXME`。

## 清单与生成物

`package.json` 字段顺序以 `scripts/lib/package-manifest-order.cjs` 为准，格式工具自动处理。排序不修改字段值和依赖映射内部顺序。

变更依赖后提交对应清单和 Rush 锁文件；新增包登记 `rush.json`。格式配置统一维护，不为单个文件复制一套配置。

## 提交前检查

```sh
npm run verify
git diff --check
```

`verify` 只检查格式、语法和风格。`npm run format` 会写入受管文件，`format:check` 只读；自有代码可使用 `format:owned` / `format:owned:check`。格式化后查看差异，移除无关变化。

行为变化按[测试指南](testing.md)执行相关回归；文档变化检查本地链接。客户端显示不能替代服务端授权，不提交秘密、用户数据和本机构建产物，也不通过删除数据库卷排障。
